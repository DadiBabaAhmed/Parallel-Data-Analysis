2. Docker Installation & Setup

Prerequisites

  • Docker: 20.10+ installed
  • Docker Compose: 1.29+ installed
  • Disk Space: 22 GB (4 images × 5.7 GB each)
  • RAM: 8 GB minimum (2 GB per worker + 4 GB master recommended)
  • CPU: 4 cores minimum, 8+ recommended

Quick Start (5 Minutes)

# Navigate to the project directory
cd Script/

# Start all services (Spark master + 3 workers + Web API)

# Verify all containers are healthy

4. Spark Configuration

Cluster Architecture (docker-compose.yml)

# Spark Master
spark-master:
  - Role: Driver, scheduler, and web UI
  - Hostname: spark-master
  - Port: 7077 (Spark native)
  - Web UI: 8080 (view cluster status, job history)
  - App UI: 4040 (during job execution)

# Spark Workers (3 instances)
spark-worker-1, spark-worker-2, spark-worker-3:
  - Role: Task executors
  - Cores per worker: 2 (SPARK_WORKER_CORES)
  - Memory per worker: 2G (SPARK_WORKER_MEMORY)
  - Web UI: 8081, 8082, 8083 (view executor status)
  - Total cluster capacity: 6 cores, 6 GB memory

Spark Session Configuration (in main.py)

spark = SparkSession.builder \
  .appName("Parallel Data Analysis") \
  .master("spark://spark-master:7077") \
  .config("spark.executor.cores", "2") \
  .config("spark.executor.memory", "2g") \
  .config("spark.driver.memory", "2g") \
  .config("spark.sql.shuffle.partitions", "200") \
  .config("spark.default.parallelism", "12") \
  .getOrCreate()

Key Parameters Explained

  • master: spark://spark-master:7077 — connects to cluster master
  • executor.cores: CPU cores per executor (tune based on worker capacity)
  • executor.memory: Memory per executor (avoid OOM on large datasets)
  • sql.shuffle.partitions: Number of shuffle partitions (higher = more parallelism, higher overhead)
  • default.parallelism: Partitions for RDD operations

Networking

  • All services connected via Docker network spark-network
  • Master discovered at hostname spark-master (resolved internally)
  • Workers register with master on startup
  • Host volumes mounted: ./src, ./data, ./output for data sharing

5. How the Application Operates

High-Level Workflow

  1. Entry Point (main.py): CLI parses arguments (input file, analysis type, master URL)
  2. Initialize SparkSession: Connects to cluster master on spark://spark-master:7077
  3. Load Data (DataLoader): Reads CSV/JSON/Parquet/Avro from /app/data/input/, infers schema, caches DataFrame
  4. Analyze (DataAnalyzer): Coordinates job execution via spark_jobs helpers (aggregation, statistics, MapReduce)
  5. Generate Graphs (GraphGenerator): Samples results, converts to pandas, creates visualizations (PNG/HTML)
  6. Save Results (main.py): Writes Spark results to disk and persists metadata/JSON summaries
  7. Monitor & Log (PerformanceMonitor, ErrorHandler): Track timing and handle errors throughout

Data Flow (Conceptual Diagram)

Input File (CSV/JSON/Parquet)
    ↓
DataLoader.load_data()
    ↓
Spark DataFrame (cached)
    ↓
    ├─→ DataAnalyzer
    │   ├─→ spark_jobs.aggregation_job  → Aggregations, cubes, rollups
    │   ├─→ spark_jobs.statistical_analysis → Stats, correlation, anomaly
    │   └─→ spark_jobs.mapreduce_job → Word count, group operations
    │
    ├─→ Result DataFrame
    │   ├─→ Spark Writer (Parquet/CSV partitioned) → output/general/results_*_spark/
    │   └─→ Preview to Pandas (sample) → output/general/results_*.csv
    │
    └─→ GraphGenerator
        ├─→ Sample DataFrame → Pandas
        └─→ Plot (matplotlib/seaborn/plotly) → output/general/graphs/*.png

Work Division (How Parallelism Works)

Spark partitions the data across cluster:

  • Large datasets are automatically partitioned across 3 worker nodes
  • Each partition processed in parallel by executor tasks
  • Tasks scheduled by Master, executed on Workers
  • Shuffle operations (group by, join, etc.) redistribute data as needed

Example: A 1 GB CSV with 1M rows might be split into 200 partitions, each processed in parallel across 6 cores (3 workers × 2 cores each).

Analysis Types (from CLI: --analysis)

Type What It Does
statistical Descriptive stats (mean, std, percentiles), correlation matrix, distributions
aggregation Group-by aggregations, cubes, rollups, time-series binning
mapreduce MapReduce patterns (word count, moving averages, top N)
full Runs all three analyses in sequence

API Overview

The Flask-based Web API (pda-web-api) runs on localhost:5000 and exposes the following endpoints:

Core Endpoints

GET /api/health

Purpose: Health check endpoint. Returns 200 OK if API is running.

curl http://localhost:5000/api/health
Response: { "status": "ok" }
GET /api/hosts

Purpose: List cluster hosts and web UI URLs.

curl http://localhost:5000/api/hosts
Response:
{
  "hosts": [
    {"name": "Spark Master", "url": "http://localhost:8080"},
    {"name": "Spark App UI", "url": "http://localhost:4040"},
    {"name": "Worker 1", "url": "http://localhost:8081"},
    ...
  ]
}
GET /api/input-files

Purpose: List available input files in /app/data/input/.

curl http://localhost:5000/api/input-files
Response:
{
  "files": [
    {"name": "sample_sales.csv", "size": 73000},
    {"name": "spotify_data clean.csv", "size": 1378000},
    ...
  ]
}
GET /api/results

Purpose: List generated results (graphs, CSV, analysis JSON).

curl http://localhost:5000/api/results
Response:
{
  "results": [
    {"type": "csv", "name": "results_20251205_120000.csv", "path": "..."},
    {"type": "graph", "name": "distribution_*.png", "path": "..."},
    ...
  ]
}
POST /api/trigger

Purpose: Trigger a new analysis job. Spawns analysis in background.

curl -X POST http://localhost:5000/api/trigger \
  -H "Content-Type: application/json" \
  -d '{"input_file":"sample_sales.csv","analysis_type":"full"}'

Response:
{
  "job_id": "abc-def-123",
  "status": "queued",
  "created_at": "2025-12-05T12:00:00Z"
}
GET /api/jobs

Purpose: List all jobs (current and historical).

curl http://localhost:5000/api/jobs
Response:
{
  "jobs": [
    {"id": "abc-def-123", "status": "running", "progress": 45},
    {"id": "xyz-123-abc", "status": "completed", "progress": 100},
    ...
  ]
}
GET /api/job/<job_id>

Purpose: Get detailed status and metadata for a specific job.

curl http://localhost:5000/api/job/abc-def-123
Response:
{
  "id": "abc-def-123",
  "status": "running",
  "progress": 75,
  "started_at": "2025-12-05T12:00:00Z",
  "input_file": "sample_sales.csv",
  "analysis_type": "full"
}

Integration: The dashboard (dashboard.html) uses these endpoints to display input files, trigger jobs, poll status, and display results. The frontend polls /api/job/<id> every 2 seconds during execution.

Common Issues & Solutions

❌ Containers won't start

Cause: Port conflict, insufficient resources

Solution: Check docker-compose logs, free up ports 8080-8083, ensure 8GB RAM available

❌ Web API not responding

Cause: Container crashed, Flask not listening

Solution: docker-compose ps check status, docker-compose logs web_api see errors

❌ Python module not found

Cause: Using wrong Python binary

Solution: Always use /opt/conda/envs/pda/bin/python inside containers

❌ Jobs timeout or hang

Cause: Large dataset, shuffle operations, network latency

Solution: Check Spark Master UI (8080), increase partition count, reduce sample size in GraphGenerator

❌ Results not saved

Cause: Output directory permissions, missing mount

Solution: Verify ./output mounted in docker-compose.yml, check job logs for errors
